# VA-11 Hall-A companion — VAllhalla 1.0.0

A bartending panel for the second screen while VA-11 Hall-A runs on the main one. Drag cans into
the shaker, toggle Ice and Age, shake the shaker with your finger (or tap Mix / press ZR), watch
the blend bar fill, then get SUCCESS or the error windows, and Serve or Reset. The panel reads the
game's own state (shaker contents, Ice, Aging, mixing, the night's money, one or two customer
slots), so it stays in sync whichever screen you pour with.

When the game is not at the bar, the panel shows a stand-by screen: Jill at the counter during
dialogue, with her face following the scene, or the game's break doodles, the title screen's Jill
and a "Please Stand by" pulse. A tap on Jill's scene advances the dialogue; a held finger on the
stand-by screen opens the bar anyway.

## Supported input

- Title `010086500D3C8000`, base game v0, main build `32D80C9AFC27E2EFEBAA048B1E6A120C`
  (checked against the NSO by `tools/va11-hall-a/gen_load_plan.py --verify`).
  `package.json` lists that build only (`tools/va11-hall-a/build_ids.txt`); on any other build the
  companion does not load. The guest load plan is pinned to the full build ID and checks every
  patched byte.
- Eden Duo 1.3.0 or newer (`min_runtime` 20).
- Tested on an AYN Thor (Android arm64), English. Desktop builds of the module are not tested.

## What the module does

`native/modules/010086500D3C8000.cpp` (target `dsmod-va11`):

- Reads the game's GameMaker state: the talking/mixing switch (found by a heap scan, since its
  address changes every boot), the shaker contents, Ice, Aging, mixing, the room, save and load.
- Decodes every game picture it shows (cans, shaker, buttons, drinks, Jill, the doodles, the
  title Jill) and the game's sounds (OGG, through stb_vorbis) from the player's own
  `romfs:/game.win` at runtime, and reads Jill's dialogue lines from the player's own script files
  to know which line is on screen.
- Never writes the game's memory directly. It asks the package to press ZR, ZL and A (start or
  stop a mix, Reset, the next dialogue line), and calls a few of the game's GameMaker built-ins
  through the guest mailbox of `guest/<build>/load-plan.json`: `audio_play_sound` /
  `audio_sound_gain` (the ice in the shaker, the error-window click, the easter egg),
  `variable_global_get("language")` (which script folder to read), and `variable_global_set` on
  `MOUSE_SHIFT_X/Y`, so the game's cursor is inside the text box before the A of a dialogue tap.
  The plan points two `bl`s in the VM's built-in call at a small stub in the zero padding after
  `.text`; the stub serves at most one mailbox request per call, on the game's thread.
- A bottom-screen mirror of the song picker, built on the same calls (`ds_list_set`,
  `instance_create`, ...), is still in the source but switched off (`kJukeboxMirror = false`).
  `tools/va11-hall-a/gen_load_plan.py --verify <main>` regenerates it and checks it against the
  player's own `main`.

## Game assets

Nothing from the game ships. The package holds only:

- original art by Mati: the SUCCESS popup, the error windows and their glitch frames, the
  tutorial hand and filters, the heart and the drawing in the note under Age;
- art generated by `tools/va11-hall-a/` (counter, Jill's shadow, neon layers, dust, dither
  tiles), and three plain pieces drawn for the project with no generator kept: the bar window
  (`bg_bar_window.png`, 68 colours on a 310x270 grid at 4x), the panel frame (`panel.png`, 6
  colours) and the drink bubble (`bubble.png`, one 7x7 dot);
- the PixelMplus12 font by itouhiro (M+ FONT LICENSE, `dualscreen/LICENSE-PixelMplus.txt`).

`native/modules/va11_jill_faces/*.tsv` are our own reading of each day's scenes: a script line
number and a face name per entry, no game text.

## Building

```sh
python3 tools/va11-hall-a/gen_jill_faces.py      # only after editing va11_jill_faces/*.tsv
cmake --build <android build> --target dsmod-va11
llvm-strip --strip-all -o va11.so <android build>/010086500D3C8000.so
python3 tools/build_dualscreen_package.py --package packages/VA11HallA \
  --output 010086500D3C8000.dsmod.zip --module android-arm64-v8a=va11.so --abi 1 \
  $(sed 's/^/--build-id /' tools/va11-hall-a/build_ids.txt)
```

`dsmod-va11-test` (BUILD_TESTING, desktop) runs the module against fake guest memory and a
synthetic `game.win`.
